# Resident repo environments

One always-warm service per onboarded repo: a dedicated resident Worker (`switchboard-resident`) fronts per-resource Durable Objects on Cloudflare Sandbox 1.0 (`@cloudflare/sandbox@next`, exact-pinned). Residency is a generic resource-typed primitive — every route carries a `resource` id of the form `<type>:<id>` (`repo:<slug>` is the first and only type), and the Durable Object name IS the resource id. This file covers the U2 surface: auth scopes, the atomic cap, onboard/offboard/reconfigure/status/residents, and the x-env hardening. The lifecycle engine (warm/refresh/restore, watchdog re-arm/degrade) and the operator data plane (/attach /exec /read /write, /op) land in later units and will extend this file in their PRs.

- **Code**: `deploy/cloudflare-resident/` (worker.ts, wrangler.jsonc, Dockerfile)
- **Docs**: [AGENTS.md](../AGENTS.md); the thread-sandbox counterpart is [execution.md](execution.md)
- **Tests**: none (deploy/* convention: Worker code is verified by `npm run typecheck` in `deploy/cloudflare-resident` plus the live checks below; the repo's vitest covers `src/**` only)

Base URL for all `[agent]` checks: `https://switchboard-resident.coreplanelabs.dev`. `$ADMIN` / `$OPERATOR` are the `RESIDENT_ADMIN_TOKEN` / `RESIDENT_OPERATOR_TOKEN` secrets (`npm run secrets` in `deploy/cloudflare-resident`).

## Behavior

1. **Two bearer scopes, fail closed**: the admin token guards `POST /onboard`, `POST /offboard`, `POST /reconfigure`, `GET /residents`; the operator token guards `POST /attach /exec /read /write /op` and `GET /status`. Admin is a strict superset (valid on operator routes); the operator token never opens an admin route. Comparison is constant-time (byte-XOR accumulate), never a plain `!==`. Unset/empty secrets grant nothing; unknown paths answer 401 before revealing 404. The only unauthenticated route is `GET /healthz` (deploy wake ping; touches no DO, returns `{ok:true}`).
2. **Atomic cap**: the singleton `ResidentRegistryDO` holds the onboarded set + command table and enforces `RESIDENT_CAP` (8) in one input-gated read-count-insert — an over-cap onboard is refused with 429 by the registry, never by the platform (`max_instances` is 10, deliberately above the cap).
3. **Onboard returns immediately**: `POST /onboard {resource, commands:{test,build,...}, defaultRef, diskBudgetMb?, provisioningTimeoutMs?}` validates, inserts into the registry, persists state `onboarding` on the resident DO, arms the provisioning deadline (via the Container `schedule()` API — never the raw DO alarm slot, which the Sandbox base class owns), and answers 202 without starting a container. If arming the resident fails, the registry slot is freed (no half-onboarded residents).
4. **Command table is admin-writable only** (KTD9 storage half): commands exist solely in the registry and change solely through `/onboard` and `/reconfigure` (admin scope). `commands` must include `test` and `build`; extra named commands are allowed; `reconfigure.commands` replaces the whole table.
5. **Offboard is a full teardown**: registry removal first (slot frees atomically), then resident teardown (cancel schedules, best-effort container destroy, DO storage wipe), then deletion of every R2 object under the resource prefix `resident/<resource>/`. The response itemizes what was deleted.
6. **Lifecycle states are persisted, engine pending**: states are `onboarding|warm|refreshing|restoring|degraded|down`, with a `reason` string required on every degraded/down. U2 sets `onboarding` on onboard and fails closed to `degraded` when the provisioning deadline passes (the U3 engine replaces that stub). `GET /status` (operator) returns exactly `{state, reason}` — operators see lifecycle, not config.
7. **x-env hardening**: caller-supplied `x-env-*` headers are ignored on every route (nothing reads them; no request header is forwarded into a resident — a deliberate deviation from the thread-sandbox Worker). Env names the resident itself injects must match `^[A-Z_][A-Z0-9_]*$` (`validateEnvNames` in worker.ts) before interpolation.
8. **Version pinning is exact**: `@cloudflare/sandbox` is pinned to `0.13.0-next.751.1` in package.json and the Dockerfile `FROM docker.io/cloudflare/sandbox:` tag must match it exactly — bump both together. KTD4 pairing: watchdog cron (10 min) < `SLEEP_AFTER` (20 min). KTD5: the image provisions unprivileged users `worker1..worker8` (uid 2001–2008); sudo is absent and root's password is locked, so `su` demotion works one way only.
