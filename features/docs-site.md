# Docs site: the `docs/` tree, compiled and hosted

The human-facing docs ([`docs/`](../docs/README.md), organized by [Diataxis](https://diataxis.fr)) are published as a static site — searchable, dark/light, with mermaid diagrams rendered — **without ever ceasing to be the markdown that renders on GitHub**. There is one tree, one source of truth, two surfaces: a reader on github.com follows a relative `.md` link to the file, and a reader on the site follows the same link to a clean URL, because the compiler rewrites it.

The mechanical half of the reference pages is not written by hand at all: every command table comes from the command registry ([command-registry.md](command-registry.md)) through a generator, and CI fails when the committed tables and the code disagree. That is what "docs change as the code changes" means here — not a reminder, a check.

The site is an **assets-only Cloudflare Worker**, deliberately not part of the bot's Worker: a docs typo must never require a container rollover (the deploy hazard in [slack-channel.md](slack-channel.md) items 7–8), so docs deploy from CI in seconds while the bot's own deploy stays hand-driven and preflighted.

- **Code**: [`docs/.vitepress/config.ts`](../docs/.vitepress/config.ts) (the compiler: `rewrites`, `srcExclude`, dead-link enforcement, mermaid, local search); [`src/docs/reference.ts`](../src/docs/reference.ts) (registry → markdown tables) and [`src/docs/regions.ts`](../src/docs/regions.ts) (generated-region surgery); [`scripts/docs-gen.ts`](../scripts/docs-gen.ts) (`npm run docs:gen` / `docs:check`); [`src/core/docsLink.ts`](../src/core/docsLink.ts) + [`src/index.ts`](../src/index.ts) (the `/docs` redirect); [`web/src/components/DocsLink.vue`](../web/src/components/DocsLink.vue) + [`web/src/components/AppShell.vue`](../web/src/components/AppShell.vue) (the header link); [`deploy/cloudflare-docs/`](../deploy/cloudflare-docs/wrangler.jsonc) (the Worker); [`.github/workflows/ci.yml`](../.github/workflows/ci.yml) (the `docs` and `docs-deploy` jobs).
- **Tests**: [`src/docs/reference.test.ts`](../src/docs/reference.test.ts), [`src/docs/regions.test.ts`](../src/docs/regions.test.ts), [`src/core/docsLink.test.ts`](../src/core/docsLink.test.ts), [`web/src/components/AppNav.test.ts`](../web/src/components/AppNav.test.ts).

## Behavior

1. **One tree, two surfaces.** The site is built in place from `docs/` (`docs/.vitepress/`), never from a copy. A relative in-tree link (`reference/cli.md`) resolves on GitHub to the file and on the site to `/reference/cli`. A link that leaves the tree (root `README.md`, `AGENTS.md`, `features/*.md`) is written as an absolute repo URL, because only that form resolves on both surfaces. Those absolute URLs are linted (`src/docs/links.test.ts`): the site's dead-link check sees internal links only, and a malformed separator (`https:///host`) is invisible to a URL parser too — for `http(s)` the WHATWG parser collapses the extra slashes, so such a link still reaches the right page — which leaves a literal check as the only thing that can hold the line.
2. **`README.md` is the directory index on both surfaces.** GitHub renders a directory's `README.md` when you browse to the directory; the compiler's `rewrites` map every `README.md` to that directory's `index.html`, so a bare `[Tutorials](tutorials/)` link works in both places. Each of the four Diataxis directories carries one, and it says what that kind of page is for.
3. **`docs/plans/**` is not published.** Dated implementation plans are working documents for the repo, excluded by `srcExclude`; they stay readable on GitHub.
4. **A dead internal link fails the build** (`ignoreDeadLinks: false`), so a renamed or deleted page cannot merge while links still point at it.
5. **Mermaid renders on both surfaces.** A ```mermaid fence is a diagram on GitHub and a rendered diagram on the site (`vitepress-plugin-mermaid`, bundled — the page fetches nothing from a CDN at runtime).
6. **The mechanical reference tables are generated, and the markers say so.** A region between `<!-- generated:<name> · … -->` and `<!-- /generated:<name> -->` is written by `npm run docs:gen` from the command registry and by nothing else. Today: `cli-commands` in `reference/cli.md` (every command in CLI form, with the surfaces it reaches), `chat-commands` in `reference/slack-commands.md` (the chat-reachable subset, with who may run each), `api-routes` in `reference/dashboard-routes.md` (`/api/<group>.<verb>`, methods from the effect, scope).
7. **The generator writes only between the markers** and is idempotent: regenerating identical content reports no change. A missing marker, an unclosed region, or a marker no renderer owns is a reported problem — never a silent no-op, which is the drift this mechanism exists to prevent.
8. **`npm run docs:check` is the drift gate.** It re-renders every region and exits non-zero, naming the file, when the committed text differs — the same discipline `skills:check` applies to vendored skills. It needs no network, no config, and no deps beyond the registry, so it runs from a bare worktree.
9. **Table-safe rendering.** `describe` texts are code, not prose written for a table: a `|` is escaped, newlines are flattened, and a bare `<agent>` is escaped to an entity — but never inside an inline code span, where an entity would render literally. (An unescaped `<agent>` is an invisible HTML tag on GitHub and an unknown component to the compiler's Vue pass.)
10. **`/docs` is the stable in-product path.** `GET /docs` → `302` to the docs site's home; `GET /docs/<path>` → `302` to `<path>` on the docs site, so a deep link can be typed, bookmarked, or shared. The target is a deploy constant (`DOCS_BASE_URL` in `src/core/docsLink.ts`), overridable by the `DOCS_BASE_URL` env var for local development, and never taken from the request — there is no open redirect. The path is not in the Access-gated set: the redirect is public, the destination is not. The startup log states where `/docs` points.
11. **Every dashboard page links to the docs.** The shared header (`/runs`, `/runs/:id`, `/runs/scheduled`, `/residents`, `/residents/:owner/:name`, `/costs`) carries a docs icon button that opens `/docs` in a new tab — the app knows the path, never the docs hostname. It is not a fourth section in the site nav (it leaves the app), and below `sm` it folds into the hamburger menu as its own group above the sections.
12. **CI deploys the docs; nothing else does.** The `docs` job runs `docs:check` and builds the site on every PR and push. The `docs-deploy` job runs only on `main`, only when that push touched `docs/` or `deploy/cloudflare-docs/`, and builds before uploading so a stale `dist` cannot ship. With no `CLOUDFLARE_API_TOKEN` repository secret it logs a warning and skips rather than failing the build; when the changed-file diff cannot be computed it deploys (fails open toward freshness). `CLOUDFLARE_ACCOUNT_ID` is never set in CI — the account is pinned in `wrangler.jsonc` and the env var would override it.
13. **The docs Worker cannot disturb a run.** It has no `main`, no Durable Object, and no container, so it has no rollout, no drain, and no preflight; deploying it while a run is in flight is a no-op for the bot.
