# Reading diff

Every PR review run carries the change **as a reviewer reads it** — a `review_artifact` run event holding either the full `git diff` or [meat.dev](https://github.com/boldsoftware/meat)'s abridged *reading diff* (the conceptual meat of agent-written code: style, imports and mechanical noise dropped; concepts, algorithm choices and architecture kept). Which producer is a **deploy-level switch**; the system functions identically either way — the only observable difference is the artifact's `poweredBy` (and meat's one-line summary). This is the data half of the review panel (the run-page slideout renders it beside the Tour); the panel itself is roadmap.

Shaped on the 2026-08-30 measurement (project memory `provider-ab-harness` methodology, run on PR [#325](https://github.com/coreplanelabs/switchboard/pull/325)'s 357-line diff against the real API): Opus 4.8 abridged to 45 % kept in 96 s with everything kept load-bearing; Sonnet 5 kept 87 % in 240 s — meat needs an Opus-class model, and its latency is why production runs concurrently with the review.

- **Code**: `src/core/readingDiff.ts` (`resolveReadingDiff`, `readingDiffCommand`, `parseMeatJson`, `capDiff`, `produceReadingDiff`, `startReviewReadingDiff`, `READING_DIFF_CAP`, `MEAT_TIMEOUT_S_DEFAULT`); the `review_artifact` event in `src/core/runEvents.ts`; dispatcher wiring in `src/core/dispatcher.ts`; config `AppConfig.review.readingDiff` (`src/config.ts`).
- **Tests**: `src/core/readingDiff.test.ts`, `src/core/dispatcher.test.ts::reading-diff artifact on review runs`, `src/core/runEventLines.test.ts`, `src/core/runFriction.skillUse.test.ts` (side-fact invisibility), `src/channels/runTimeline.test.ts`.
- **Receipts**: https://github.com/coreplanelabs/switchboard/issues/225 (the review agent's receipts issue)

## Behavior

1. **The switch.** `AppConfig.review.readingDiff = { provider: "git" | "meat" | "off", meatModel?, meatTimeoutS? }`, overridden by env `SWITCHBOARD_READING_DIFF=git|meat|off` (an operator flips a deployed bot without a config rebuild; an unrecognized env value is ignored). Absent everything → `git`. `meat` means **git baseline PLUS a meat upgrade artifact** (item 4). `off` → no artifact (the roadmap's on-the-fly command is then the way to get one).
2. **One command per producer, injection-closed; meat's bound is on the producer.** `git diff --no-color --end-of-options 'origin/<base>...HEAD'` (base falls back to `origin/HEAD`), or `timeout <meatTimeoutS> meat -json [-model <m>] '<range>'` — the range and model are `shellQuote`d into inert tokens, the same discipline as `diff_digest`. `meatTimeoutS` (default 240) is meat's own runtime budget, enforced with coreutils `timeout` around the command — **the pipeline itself never waits on meat** (item 4); this is the only clock meat answers to (past it, the exec answers `exit 124` and the upgrade simply does not land). meat's `-json` wire shape (`{smart_diff, summary, input_tokens, output_tokens}`) is parsed strictly; a shell error line, non-JSON, or JSON without `smart_diff` throws.
3. **The baseline IS the fallback, structurally.** Any meat failure — binary missing, `ANTHROPIC_API_KEY` missing in the execution environment, its `timeout` firing, API error, bad output — yields no upgrade artifact and nothing else: the git baseline (item 4) already stands, so a deployment without meat behaves exactly like `provider: "git"` with no reactive fallback path to go wrong. A git failure (`exit N:`/`fatal:` first line, executor throw) or an empty diff yields no artifact and never a throw into the run. **Every string the artifact carries honors the stream's hygiene contract** (the registry publishes events as-is): the diff — git's and meat's alike — plus meat's `summary` are control-stripped and `redactSecrets`-redacted FIRST, then capped at `READING_DIFF_CAP` (120 000 chars, `…[N more chars]`, `truncated: true`, never splitting a surrogate pair) — a review of a PR that accidentally commits a credential must not carry it onto the run page or the record. The run record's own byte budget stays the outer bound.
4. **Guaranteed baseline, unawaited upgrade — no timeout races in the pipeline.** For a `review` run with a resolved PR, `startReviewReadingDiff` fires right before the model loop — the run's own executor runs the (read-only) commands beside the model's tools; events publish straight to the registry (like `input`/`run_meta`; the status card never sees them). Two productions: (a) the **git baseline**, which the dispatcher **joins** just before the answer publish — a join on a seconds-long command started minutes earlier, not a timeout — so *every PR review's record deterministically carries a reading diff*; (b) with `provider: "meat"`, the **meat upgrade**, published the moment it is done and **never awaited**: meat lands iff it finishes within the review — a later publish is dropped by the registry's existing finished-run rule and the baseline still stands. Readers prefer the meat artifact when both exist. Coding runs and PR-less reviews never produce either.
5. **A side fact, not a step.** The friction analyzer treats `review_artifact` like `skill_use` — invisible to `eventCount`, steps and turn timing; `parseRunEventLines` accepts it (reading_diff + string diff + known poweredBy); the timeline deliberately folds it to nothing until the panel renders it.

6. **The pr-review module renders it** (`web/src/modules/pr-review/` — a deliberately liftable, props-only Vue module; see its README). Contract: `PrReviewData = { pr: PrRef, readingDiffs: ReadingDiff[] }` — the module imports nothing from the app's lib/pages or anything runs-shaped, so the whole folder can be shared into another product (nominal) with the host writing its own adapter. `PrReviewPanel` shows GitHub links built only from shape-verified values (`prLinks`: `owner/name` + positive integer + 7–40-hex sha; anything else renders as text), producer tabs when both diffs exist (`preferredDiff`: abridged first), and `ReadingDiffView` renders each diff with diff2html (line-by-line; the library escapes diff content — hostile diff text is never markup), producer/truncation badges and the producer's summary. **Switchboard's adapter** is `web/src/lib/prReviewCollector.ts` — the one place run shapes meet the module: `run_meta` → the PR identity, `review_artifact` → the diffs (one per producer, a later artifact replaces its producer's earlier one — a same-run re-review), malformed frames ignored. The run page feeds the collector the same frames as the timeline (seeded history and live SSE alike) and, once `ready` (at least one diff), shows a **Reading diff** button on the run-meta line that opens the panel in a slideout. Coding runs and reviews with the provider `off` never light the button.

## Deploy prerequisites for `provider: "meat"`

Not part of this feature's code, and `git` is the default until they land: the **meat binary** in the review execution image(s) (resident + sandbox; it is a static Go binary, `go build ./cmd/meat` from [boldsoftware/meat](https://github.com/boldsoftware/meat)) and an **`ANTHROPIC_API_KEY` in that execution environment** (meat makes its own model calls; pin `meatModel` to an Opus-class model). Until both exist, `provider: "meat"` behaves exactly like `provider: "git"` — the upgrade production fails fast (`command not found`), publishes nothing, and the guaranteed git baseline stands.

## Roadmap (gaps)

- `[gap]` **On-the-fly production** when `off`, or a meat upgrade for a run whose review ended first: a registry command (and panel button) that produces a reading diff for a PR after the fact. (If "meat-powered whenever enabled" ever needs to be a hard guarantee, the mechanism is a run-record append after the fact — a run-history contract change — never a pipeline wait.)
- `[gap]` **The PR description in the panel**: render the `PrDescription` object ([pr-description.md](pr-description.md)) beside the reading diff once `submit_pr_description` gives runs the object; the module's contract gains an optional `description` field then.
- `[gap]` **meat in the images + key provisioning** (deploy work, above).
