# Controlled acceptance source (isolated)

This is a standalone Streamable HTTP MCP fixture for a read-only slow-source drill, not a production source or a product fix. The local `wrangler.toml` is intentionally **not** a generated `wrangler.jsonc`: `deploy:gen` owns the other Workers' templates, while this Worker is neither in the deploy profile nor the deploy target manifest. No route, account, compatibility date, credential, fixture data from a provider, or production MCP connection is defined here. The drill owner must supply a compatibility date with Wrangler when deploying; deployment, secrets, grants, and the live test belong outside this PR.

The operator must provide `SOURCE_BEARER` as a secret binding, `SOURCE_REQUESTER` as the one requester identity, and `SOURCE_RESOURCE_SCOPE` as a comma-separated subset of `quick,slow`; missing bindings refuse every request. The bearer is never stored in the Durable Object, emitted in a response or logged. The isolated `AcceptanceActions` Durable Object records the session and each action before the worker waits. The `slow` alarm completes a durable readback after 35 seconds even when the original client disconnects at its 30-second timeout. Only the original session can inspect the same action. The diagnostic is a bearer- and session-gated GET `/diagnostic/<opaque-action-id>` with stage and timestamps only. A real release and an independent live result check remain separate acceptance work, not proof supplied by these fixtures.

The workspace `verify` script runs a scoped TypeScript check and its Vitest file. It deliberately has no `test` script: the root Vitest project's workspace guard would otherwise require touching files outside this unit's reserved paths. CI's workers matrix selects this workspace through `ci:plan` when its files change; it never selects a deployment image for it.
