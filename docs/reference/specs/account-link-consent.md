# Staged account-link consent

The browser slice of [the proposed linking design](../../decisions/0081-account-linking-proves-both-identities-and-revocation-fences-their-use.md) composes the [offline proof adapters and atomic directory](person-directory.md). The record remains proposed. This is an isolated local fixture, not an enabled account feature; no production route, OAuth configuration, authorization consumer, history migration or email-bridge cutover changes.

- **Code**: `src/channels/linkBrowser.ts`, `src/core/identity/linkCeremony.ts`, `web/src/modules/account-linking/LinkConsent.vue`, `web/src/modules/account-linking/fixtures.ts`, `web/src/modules/account-linking/preview.ts`, `web/link-consent-preview.html`.
- **Tests**: `src/channels/linkBrowser.test.ts`, `web/src/modules/account-linking/LinkConsent.test.ts`.

## Behavior

1. **Disabled means unreachable.** The HTTP adapter returns 404 by default, before reading credentials or touching a provider or directory. Explicit local-fixture mode additionally requires an exact HTTPS loopback origin. Nothing registers it in the production server or router. The separate Vite fixture entry uses made-up identities only, not real credentials or requests to Slack.
2. **The browser is bound, not a person selector.** A Secure, HttpOnly, SameSite=Lax, host-only cookie carries the opaque operation and independent browser secret. Lax permits the top-level OAuth return. The URL, form and JSON view never carry that secret, a person target or a credential. Same-origin POSTs also require a form token bound to the cookie and exact action; closed forms reject extra or duplicate fields. The callback instead uses the stored one-time state and authenticated browser.
3. **Consent is local and explicit.** After callback, a clean URL displays the verified Access issuer/subject/audience and signed Slack user/workspace identifiers, not email/name matches or a requested team hint. Only an explicit checkbox and protected final POST can call the atomic transaction. The server reauthenticates Access at callback, display, consent, cancellation, interruption and receipt read. The store enforces the original tuple/audience/browser, state/revision, unchanged or shortened deadline and current directory revisions. Refresh never extends the intent.
4. **Retries are not new links.** Callback replays never exchange a second code. An uncertain exchange stays claimed across reconstruction; an explicit protected interrupt makes it terminal without retrying credentials. Cancellation and expiry cannot link. Duplicate final POSTs and response-loss retries return the existing terminal outcome within the original result window, not another person, binding receipt or operation audit. A same-origin, cookie-bound restart is offered only after a cancelled, failed or expired verification. It rotates to a fresh browser seed when chosen; the old cookie can still read its result during the original window. A committed intent remains ineligible for restart after its result window closes; the browser shows only that the result is no longer retrievable.
5. **No credential-bearing rendering.** The callback always returns a bodyless 303 to the clean consent address, including failures. Every adapter response carries no-store, no-referrer and a restrictive CSP. Only allowlisted verified metadata enters views or the directory; provider errors and raw callback parameters are never reflected. There is no logger, run-event sink, credential cache or audit hook on the browser adapter. Edge/proxy query redaction is a separate deployment obligation, not a claim about this unwired handler.
6. **UI isolation.** The consent module uses the current Vue/Nuxt UI tokens and explicit props; it does not modify the production app shell, route or seed union. The fixture entry supplies start, consent, exchanging, committed and refusal states in either theme. It demonstrates local consent without granting cross-surface access.
