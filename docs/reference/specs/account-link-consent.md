# Staged account-link consent

The browser slice of [the proposed linking design](../../decisions/0081-account-linking-proves-both-identities-and-revocation-fences-their-use.md) composes the [offline proof adapters and atomic directory](person-directory.md). The record remains proposed. The optional host handler now accepts explicit Access and Slack proof configuration; this slice does not register a production route, authorization consumer, history migration or email-bridge cutover. The existing local fixture remains separate.

- **Code**: `src/core/commands/identity.ts`, `src/core/commands/all.ts`, `src/channels/identityRuntime.ts`, `src/channels/identitySeed.ts`, `src/channels/webSeed.ts`, `src/channels/webShell.ts`, `src/channels/linkBrowser.ts`, `src/core/identity/linkCeremony.ts`, `web/src/modules/account-linking/LinkConsent.vue`, `web/src/modules/account-linking/fixtures.ts`, `web/src/modules/account-linking/preview.ts`, `web/link-consent-preview.html`.
- **Tests**: `src/core/commandConformance.test.ts`, `src/channels/identityRuntime.test.ts`, `src/channels/linkBrowser.test.ts`, `web/src/modules/account-linking/LinkConsent.test.ts`.

## Behavior

1. **Disabled means unreachable.** The HTTP adapter returns 404 by default, before reading credentials or touching a provider or directory. Explicit local-fixture mode additionally requires an exact HTTPS loopback origin. The optional host handler supplies production mode only with an explicit HTTPS origin, current human Access proof, directory and named Slack secret. Nothing registers that handler in the production server or router in this slice. The separate Vite fixture entry uses made-up identities only, not real credentials or requests to Slack.
2. **The browser is bound, not a person selector.** A Secure, HttpOnly, SameSite=Lax, host-only cookie carries the opaque operation and independent browser secret. Lax permits the top-level OAuth return. The URL, form and JSON view never carry that secret, a person target or a credential. Same-origin POSTs also require a form token bound to the cookie and exact action; closed forms reject extra or duplicate fields. The callback instead uses the stored one-time state and authenticated browser.
3. **Consent is local and explicit.** After callback, a clean URL displays the verified Access issuer/subject/audience and signed Slack user/workspace identifiers, not email/name matches or a requested team hint. Only an explicit checkbox and protected final POST can call the atomic transaction. The server re-verifies the current signed Access session at callback, display, consent, cancellation, interruption and receipt read. The session may predate the challenge: freshness means a new operation-bound target proof and local consent, not a new identity-provider login or a token-issuance timestamp. The store enforces the original tuple/audience/browser, state/revision, unchanged or shortened deadline and current directory revisions. Refresh never extends the intent.
4. **Retries are not new links.** Callback replays never exchange a second code. An uncertain exchange stays claimed across reconstruction; an explicit protected interrupt makes it terminal without retrying credentials. Cancellation and expiry cannot link. Duplicate final POSTs and response-loss retries return the existing terminal outcome within the original result window, not another person, binding receipt or operation audit. A same-origin, cookie-bound restart starts a fresh verification after a terminal operation, including a committed link. It rotates to a new browser seed; the old cookie can still read its result during the original window. An expired result does not restore old proof or mutate the saved binding. Active operations cannot restart.
5. **No credential-bearing rendering.** The callback always returns a bodyless 303 to the clean consent address, including failures. Every adapter response carries no-store and a restrictive CSP. JSON, callbacks, redirects and refusals use no-referrer. Only the clean hosted HTML form with status 200 uses same-origin so local POSTs retain their actual Origin; cross-origin provider navigation still sends no referrer. Only allowlisted verified metadata enters views or the directory; provider errors and raw callback parameters are never reflected. There is no logger, run-event sink, credential cache or audit hook on the browser adapter. Edge/proxy query redaction is a separate deployment obligation, not a claim about this unwired handler.
6. **UI isolation.** The consent module uses the current Vue/Nuxt UI tokens and explicit props; it does not modify the production app route. A typed identity seed and explicit form CSP option support the optional handler without registering it. The fixture entry supplies start, consent, exchanging, committed and refusal states in either theme. It demonstrates local consent without granting cross-surface access.

## Optional host handler

`createIdentityRuntime` composes the existing two-account ceremony. It requires the current human Access account and a host authorization callback for writes. Service credentials, view-as and cross-site posts cannot bind accounts. Missing configuration, directory, Access application or named secret remains unavailable. The handler carries protected forms and pins the Slack provider in its form CSP; it does not mount a new app route or persist OAuth credentials.
