# Main agent actions on linked work

The main agent addresses one existing Ship unit by the durable `(main thread, act id)` link. The requester's resolved identity and current thread are trusted context; model text cannot pick another task or requester. This service does not start a worker or expose its private brief.

- **Code**: `src/core/coordinator/mainActions.ts`, `src/core/coordinator/instanceStore.ts`, `src/core/coordinator/contract.ts`, `src/core/planeService.ts`, `src/core/authz/policy.ts`
- **Tests**: `src/core/coordinator/mainActions.test.ts`, `src/core/authz/policy.test.ts`

| Criterion | Proof |
|---|---|
| Status reads the exact linked unit for the requester in the current main thread. It returns a small status, branch and pull request projection without the brief, private thread, run ids, or report. Missing, stale, foreign and cross-thread links reveal no task facts. | `[unit]` `src/core/coordinator/mainActions.test.ts::main task actions::status projects only the requester's linked unit without private context`; `::a foreign or cross-thread caller cannot read the link` |
| Steering writes a bounded event under a stable action id to that unit and nudges its Workflow. An orchestrator acting for the bound requester writes the requester's sender id so an idle unit recognizes the wake. Repeating the same action appends no second event; reusing its id with different words refuses. A failed nudge leaves the event queued for the coordinator's next read. A stopped, ended, recovered, or mismatched unit receives no event. A later whole-row update cannot rewrite a claimed brief. | `[unit]` `src/core/coordinator/mainActions.test.ts::main task actions::steer persists one event and a replay cannot change its words`; `::a main-agent steer wakes as the bound requester`; `::a failed nudge leaves the event queued`; `::terminal units refuse a steer and a later brief rewrite cannot change the binding`; `::a mismatched stored brief refuses a steer before writing an event` |
| A requester can stop their own linked work without an operator grant. The narrow policy row checks self identity, and the service checks the exact main thread and unit before calling the existing plane stop. Its answer reports the runner mark and child outcomes without claiming completion when the mark failed. A stop targets only child runs tagged with that instance, even when unrelated runs share a unit thread. A foreign, view-as or non-person caller changes nothing. | `[unit]` `src/core/coordinator/mainActions.test.ts::main task actions::stop preserves exact ownership and reports the plane outcome`; `src/core/authz/policy.test.ts::main task stop authorization::admits only the requester without an operator grant`; `src/core/planeService.test.ts::plane stop — the runner_stop move (record 0064; issue 1924)::terminates the instance and ends its live children in one move: the stop mark first, the hosted parent hard-stopped, then every live child in a unit thread — never the parent twice` |
| The main agent can start and bind a private worker and deliver a steer to a currently running coding child. | `[gap]` Typed tool registration, private child live delivery, and main-thread progress relay are integration work; this service queues input for the existing coordinator fold. |
