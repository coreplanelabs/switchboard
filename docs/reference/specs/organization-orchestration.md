# Organization orchestration

One organization has one logical orchestrator identity. Its durable admission ledger preserves the authenticated source actor, addressed private stream, receipt and reconciliation lease. Existing unit owners retain execution authority.

The server composes these contracts through authenticated adapter mappings and configured retention and admission limits. The server does not infer an organization or person from message text, repository, email or attached context. The server wires browser, Slack, HTTP and MCP intake, account verification routes and canonical owner effects. Unavailable source proof holds work; it never selects a replacement owner.

## Behavior

1. **Authenticated organization first.** Exact authenticated source, issuer and tenant map to one organization. CLI, HTTP and MCP also require an explicit caller organization grant. Absent and ambiguous mappings fail closed. GitHub admits only a proved human's local answer to an observed unit question.
2. **Private projection preserves identity.** A proved person binding joins only future admitted conversation. Every reply inherits its original request's admission boundary; a late reply cannot expose a pre-link request. A legacy entry with no admission boundary is readable only through its own current source. Historical actors and authorization receipts remain unchanged. Unlinked human sources have separate streams. Services retain separate principals; a verified delegation preserves its source identity while projecting to the addressed person's stream. Before a proved person binding, that delegation uses only the credential's own source stream; it does not infer a Person ID or join peer history. An unlink tombstone supplies the current source-only revision and fences older queued owners. Local thread messages never copy into the broad stream.
3. **One durable admission transaction.** Organization, source identity and key scope a receipt. Equivalent validated fields return the original disposition regardless of object property order. Array order and raw input content remain part of the payload; binding projection changes do not change its digest. A changed payload under that key conflicts. New keys are distinct acts. Browser keys are minted by the server, expire before first use and bind the current actor revision. An existing receipt remains replayable after key expiry.
4. **Reservations do not own unit state.** The ledger records an observed canonical target version and reserves it for one admitted receipt. It never increments the canonical version on admission. Rejection, deletion, retention or revoked authority release that exact reservation. Accepted reservations remain until the canonical owner reports a newer version. The canonical unit owner must independently authorize and compare its full question state before accepting an answer.
5. **Fenced reconciliation.** A replacement process acquires the same logical identity with a new lease generation. Selection excludes later admissions outside the claimed snapshot. Bounded batches rotate source and actor lanes with a durable cursor; ordinary requests cannot use reserved reconciliation capacity. Completion refuses while eligible work in that snapshot remains pending. The runtime releases that finished batch through the fenced yield command, without marking the remaining snapshot reconciled or waiting for its launched model runs. Pending caps bound queued submissions; the original execution engine retains its separate live-run and compute ownership.
6. **Effect keys do not prove an external effect once.** Pending selection is repeatable after process replacement. The existing execution owner must atomically consume the preserved effect key before dispatch or resume. The ledger alone cannot prevent a repeated network effect after a crash between effect and settlement. Admission and settlement are separate facts.
7. **Current authority at every read and act.** Admission, stream reads, selection and settlement check the binding in the same authoritative database as the identity directory. A caller revoked between service authorization and a stream transaction receives a fenced result. Source-access revocation stops admission, queued effects and source transcript disclosure. Effect authorization rechecks the preserved actor, source access, content lifetime, canonical target version, receipt and current lease before the owner consumes its key.
8. **Content lifecycle and safe updates.** Secrets are redacted before durable input and reply storage. Every constructed pending, stream and receipt row must pass its stored schema. If sanitized instructions, replies or receipt reasons exceed that schema, the request fails before state changes; instructions are never silently truncated. Content deletion removes transcript and queued model input while its non-content receipt still blocks replay. Expired queued content is ineligible even beyond a cleanup batch. Transcript reads use an indexed bounded cursor. Deletes, source revocations, receipt settlement and cleanup advance the projection revision. Consumers must also fence frames by the current actor binding revision.
9. **One persistence algorithm.** The in-memory and SQLite implementations run the same contract tests. The Worker stores the directory and ledger in one installation Durable Object, uses the existing bearer and request-size gates, validates both requests and responses, and refuses unknown stored schema versions without replacing their rows.

## Verified native source deletion

The internal source-address deletion command is a lifecycle fact, not a caller-selected act. The Slack adapter verifies its authenticated Socket Mode workspace against the configured bot before matching the retained source issuer, workspace, channel and immutable message timestamp. It never derives deletion authority from `previous_message.user` or text. Source deletion removes copied private entries and original queued snapshots, while canonical work, original owners and non-content receipts remain unchanged. A source tombstone rejects later admission at that same address and fences reads and effects while bounded physical cleanup remains pending. Its cursor survives replacement; the existing reconciliation loop repairs remaining copies and owner clears. Each batch scans at most the existing reconciliation bound plus one lookahead and removes at most that bound of stream entries. Completed tombstones expire after the configured content/receipt horizon or a later retained source deadline. Incomplete cleanup remains fenced until cleanup completes; it cannot expire into restored content.

Bolt normally acknowledges events before message listeners. The existing receiver-to-app seam intercepts only source deletion so successful acknowledgment follows durable copied-content cleanup and a bounded, exact-source check proving no matching snapshot clear remains. An unrelated older clear cannot consume that proof or certify the target. Unknown proof or erasure receives no success acknowledgment. Ordinary events keep the existing app handler. Deleting a native delivery projection that is not a retained ingress source does not rewrite canonical unit conversations or execution history.
