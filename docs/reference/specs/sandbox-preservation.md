# Seeded sandbox preservation

A sandbox's idle deadline must not erase an unpublished seeded checkout. The Worker is the protective boundary; attaching a future run, verified restore, publication and terminal-owner cleanup are separate work. This source change is not a deployed durability receipt.

A checkpoint is only eligible when the Worker can establish quiescence *without* trusting a model assertion; the SDK's tracked-process list does not see detached writers, so this Worker currently retains seeded containers rather than making a paused-writer backup. A never-classified older container also stays retained; only a durable pre-start unseeded classification permits normal teardown. A model-root writer can remove the filesystem marker without clearing that durable fence. The bot sends a claim only when its trusted run context includes the resolved head and complete identity; callers without those facts remain unclaimed and their receipt is `unknown`, never falsely present. Existing records without a birth origin cannot be silently upgraded by retry. The receipt does not wake a container, authorize recovery, delete a backup, or claim live durability. Operators must verify bucket lifecycle retention and a natural paused-run receipt in separately authorized work; no source-only test substitutes for those observations.
