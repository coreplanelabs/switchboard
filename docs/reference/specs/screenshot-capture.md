# Screenshot capture infrastructure

This prerequisite extends the default capture contract in [Docs site](docs-site.md), item 20. It changes no product route, component, fixture data or organization behavior. Existing surfaces keep their desktop light/dark outputs. A future isolated preview registers its own server and inputs; it does not extend the legacy fixture server merely to register a capture.

## Contract

A surface declares its local fixture server and extra configuration files. Its captures default to desktop, 1440×900 at 2×, in light and dark, with the existing `<surface>-<theme>.png` filenames. Explicit profiles select their own dimensions and suffixes (for example a phone viewport with `-phone`). A profile describes viewport capture, not mobile user-agent or touch emulation. Only supported configuration is accepted; surface names, profiles, suffixes, themes, repository input paths and local preview routes are validated before generating, deleting or overwriting outputs. Output uniqueness is checked across the entire registry.

The manifest records every resolved capture, its theme, dimensions, output filename and screenshot options, together with the fixture configuration and deterministic browser settings. Its configuration hash is canonical and surface-local. The registry is literal data: adding an independent row does not change another surface's hash. All executable capture/manifest mechanics remain shared hashed inputs. The declared fixture server and configuration files, their import dependencies, the page's imports, shared renderer, styles and tokens remain tracked. Dependency hashes select the renderer, build and capture packages and their resolved lockfile graph (including installed optional and peer dependencies), not unrelated CLI dependencies or scripts. CSS imports/plugins, bundled icon collections and the capture launcher participate too. Relevant dependency declarations and build/capture scripts remain hashed; package release labels and unrelated lockfile entries do not. Binary inputs are hashed as bytes. Missing required dependencies fail closed.

Generation and checking use the same resolver, manifest constructor and drift predicate. The clock, locale, timezone, theme initialization, reduced motion, font readiness and settle behavior stay deterministic. Compatible captures reuse the historical warm browser context per fixture and theme/profile so cold font loading does not race scroll-to-result rendering. Each fixture server accepts `PORT` and `SWITCHBOARD_PREVIEW_NOW`; captures explicitly select full capabilities and the local web bundle. Captures whose decoded pixels equal the existing PNG retain the original PNG bytes. A changed image requires a before/after comparison and an explanation, not blind acceptance of a golden.

Screenshot and manifest operations run in a short-lived output worker, leaving the generator's process-wide working directory unchanged while other threads run. The worker walks each directory component without following symlinks, verifies the opened inode against its pinned working directory, and runs synchronously before restoring it. A parent swap therefore cannot redirect existing-image reads, publication or stray cleanup. Existing files are read only through no-follow regular-file handles; publication uses a sibling temporary file and atomic rename. Import discovery uses Vue's SFC parser to select real script blocks, including mixed-case tags, while ignoring template comments and script-prefixed custom elements; malformed input fails within the test budget.
