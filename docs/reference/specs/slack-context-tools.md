# Slack context reads

The main agent can ask tools for bounded Slack context without treating messages or files as instructions. The requesting person and the bot must both be able to read each source. This is a separate, opt-in capability: merely defining the tool does not give any agent access to it.

## Prompt replay limit

Receipt survival does not prove that saved context can reach the model. The final main-agent audience gate still refuses a Slack-only seed with a nonzero log start or a compaction summary, even when its receipts revalidate. Replaying those compacted or truncated sessions remains a gap; use a fresh top-level DM message. A mixed dynamic-source continuation can proceed with a fresh prompt because its old replayable session is discarded, while its Slack dependencies remain checked.

## Retained-source bounds

A session retains at most eight receipts, 80 message hashes counted across receipts, and 32 KiB of serialized metadata. Repeated identical receipts are deduplicated; changing reads accumulate dependencies. The separate metadata allowance is below the session log's minimum 16 MiB row/attachment budget. Exceeding any bound refuses the new content and seals reuse; it never evicts earlier dependencies. Start a new top-level DM message with the source to establish fresh context. Legacy or revoked sessions follow the same reset path.

Synthetic adapter checks measure these retained nearby-read sizes: one receipt of 20 messages uses 2,715 bytes and 32 Slack calls; four of 20 use 10,101 bytes and 128 calls; eight of 10 use 11,869 bytes and 176 calls. These count fresh source/requester checks and exact-ID reads. The binding adds two destination checks per receipt plus a final check (three Slack calls each). A full pass is bounded by 227 Slack calls, plus at most eight bounded 2 MiB file downloads, before retries. Each pass has a 30-second fail-closed deadline inside the existing three-minute write-up allowance; timeout starts no further receipt. An already running adapter check may finish, but its answer cannot authorize publication. Real Slack latency and rate limiting are not proved by these synthetic counts.
