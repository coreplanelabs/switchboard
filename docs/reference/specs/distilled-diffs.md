# Distilled diffs

Before submitting its PR description the coding [agent](../vocabulary.md#agent) gets a *distilled* summary of the change, not the raw diff: per-file `+adds/-dels`, totals, and a "risky files" section that flags migrations/schema, auth/permission-sensitive files, whole-file deletions, lockfiles, and very large files. The digest shapes the submitted description — which files the Tour must walk, what belongs in risks ([pr-description.md](pr-description.md)) — so the reviewer meets the shape and the danger zones through the rendered body. The review agent uses the same digest to orient before reading.

The review agent reads the code and follows the target repository's review procedure. It runs scoped tests, lint, typecheck or build checks when that procedure requires them. If those checks need missing dependencies, it uses a frozen-lockfile install without changing tracked files. CI is useful evidence, but it does not replace a required fresh local check. Without a repository requirement, the agent uses CI and avoids duplicate checks.

The parsing/rendering core is `distillDiffStats`, a pure function over git's per-file statistics (`git diff --numstat` and `git diff --name-status` for one range; no I/O, no process, no platform SDK), so it is provider- and channel-agnostic and unit-testable in isolation. The `diff_digest` tool is the only thing that touches the world, and only through the `Executor` seam — never a direct shell-out — honoring the "tools never touch the host directly" invariant.

Why statistics and not the unified diff: every Executor caps a command's output (`truncate`, 120k characters), and the unified diff of a mid-sized PR is larger than that. The digest used to be parsed from the capped text, so it counted the first files in `git diff`'s alphabetical order and nothing after them — a 41-file, +2459/−579 PR was digested as 13 files, +144/−53, and the review approved on it. The stat listings cost one line per file, so the digest covers every file however large the change, and a listing that is itself cut is reported as incomplete rather than rendered as a smaller change. The digest states its own totals, and the review post-step holds them against the PR's size from GitHub ([agent-review.md](agent-review.md) item 15).

- **Code**: `src/core/diffDigest.ts` (the pure `distillDiffStats`, the `DigestReport` shape and its ledger parser); `src/tools/diffDigest.ts` (the `diff_digest` `RunnableTool`; reuses `src/execution/shellQuote.ts` to quote the base ref) + `src/tools/toolsets.ts` (the `full`/`readonly` toolset wiring); `src/agents/registry.ts` (`CODING_SYSTEM_RESIDENT` has the digest inform the submitted description; the three Review prompts orient with it, read the whole change, and follow applicable repository checks).
- **Tests**: `src/core/diffDigest.test.ts`, `src/tools/diffDigest.test.ts`, `src/agents/registry.test.ts`.

## Behavior

1. **`distillDiffStats` is pure and provider-agnostic**: `git diff --numstat` and `git diff --name-status` output for one range in, a compact digest out — totals line, per-file `+adds/-dels` (largest churn first), a risky-files section — plus the totals as data (`{ files, additions, deletions }`). No Executor, no filesystem, no network. Empty/whitespace input returns a clear "no changes" message with zero totals.
2. **Per-file/total counts come from the listings**: `--numstat` gives each file's added and removed lines (`-\t-` for a binary file, counted as zero); `--name-status` gives its status (added / deleted / renamed / modified) and, for a rename, both paths plainly (`R<score>\told\tnew`) — git emits both listings over the same diff queue in the same order, so they are zipped by position. A renamed file is shown at its new path, never in git's compact `{old => new}` form. A listing line that does not align keeps its numstat path and counts as modified rather than being dropped.
3. **Risky-file heuristics** (biased to over-flag — a false positive costs one glance, a missed migration costs more): path matches for migrations/schema (`migrations/`, `*.sql`, `*.prisma`, `schema`), auth/permission (`auth`, `permission`, `credential`, `secret`, `password`, `.env`, `login`, `session`, `oauth`, `rbac`, `acl`), infra/deploy/CI config (`.github/workflows/`, `*.tf`, `terraform/`, `Dockerfile`, `deploy/`, `wrangler.*`); whole-file deletions; lockfiles (exact basename: `package-lock.json`, `yarn.lock`, `pnpm-lock.yaml`, `go.sum`, `Cargo.lock`, …); and single-file churn ≥ 300 lines. Ordinary source files are not flagged. **Risk is scored against BOTH the old and new paths**, so a risky file renamed to an innocuous name (`src/auth/x.ts` → `src/misc/y.ts`, `.env` → `config.json`) is still flagged. Non-ASCII paths (git `core.quotepath` octal quoting) are decoded to the real filename.
4. **`diff_digest` tool bridges the Executor**: runs `git diff --numstat <base>...HEAD` and `git diff --name-status <base>...HEAD` — the merge-base range, never `HEAD~n` — through `ctx.executor.execResult` and renders only successful, complete listings with `distillDiffStats`. A backend without structured outcomes is refused. `base` is optional and defaults to the repo's default branch (`origin/HEAD`, falling back to `origin/main`). A caller-supplied base is `shellQuote`d into one inert token (no shell injection) behind `--end-of-options` (no git option injection; a base starting with `-` is refused before any command runs). The structured exit code determines success; stdout, stderr and display markers cannot override it. A Git failure is surfaced as an error and records an incomplete digest. **A shallow clone is deepened first**: when the listing fails without its separator and a complete, successful `git rev-parse --is-shallow-repository` answers `true` (the cold sandbox's own `git clone --depth`), the tool runs `git fetch --unshallow origin` for every branch once and retries only after a complete, successful fetch. A failed, truncated or unknown fetch is not retried. A full clone is never fetched (the resident's read-only tree has an origin it cannot fetch from by design, and its failure stays legible). **A cut listing is never a smaller change**: the Executor's structured `truncated` flag makes the tool refuse totals and report an incomplete digest, even when rendered output has no truncation marker.
5. **Enablement**: `diff_digest` is in the `full` (coding) and `readonly` (review) toolsets; `web` and `none` are unchanged. ≥2-implementations and channel-agnostic invariants hold — `distillDiffStats` is our own implementation and does not depend on `meat.dev` (absent from the node-only resident image).
6. **The digest informs the submitted description**: the resident coding prompt directs the agent to call `diff_digest` after pushing and before `submit_pr_description`, using the distilled digest — not the raw diff — to shape the description's content: which files the Tour must walk, what belongs in risks ([pr-description.md](pr-description.md) item 5). The digest is never pasted into a PR body — the agent never authors body markdown and never opens the PR.
7. **Review follows repository checks**: the Review prompts use `diff_digest` to orient before reading. All three prompt variants read applicable `AGENTS.md` and `REVIEW.md` instructions at the pinned head. They run required scoped checks and read their results before a verdict. Missing dependencies permit a frozen-lockfile install in the isolated workspace; tracked files stay unchanged. An unavailable required check leaves the review incomplete. Repository instructions do not grant code writes, a different target, extra tools or direct GitHub posting. Without required local checks, the agent uses CI and avoids duplicate checks. It keeps the existing "gather once, analyze once" discipline.

8. **One pinned PR comparison**: the controller retains the PR head and base commits from authenticated metadata. Before model work, it computes a complete digest in the acknowledged checkout. Missing pins, missing Git objects, failed commands and cut listings refuse review setup. `review_read` and `diff_digest` share the same controller target. Both compare immutable commits; neither resolves a local remote-tracking ref to choose the review base. Review prompts name those same commits. A different `base` argument is refused for a bound review and cannot replace its digest. Coding digests retain their configurable base. Each digest reports its complete totals or explicit failure through `ToolContext.onDigest`. A review report records its head, base commit, merge base and base branch. A changed head or effective comparison invalidates the previous verdict. The ledger retains the report for restart and publication. `review_digest_refused` records a bounded source category and reason; it includes no private base expression or command output.

8a. **A moved-head claim needs the native diff receipt.** The Review prompts require `review_read` diff pages for the new pinned head through source hash and EOF before that same run can claim or report a verdict at the new head. The saved bash/read diff path remains context for an initial or fixed-head review. It cannot replace the native moved-head receipt. If the native read cannot complete, this run ends incomplete and a later Review waits for verified terminal settlement.

A saved review digest without its immutable comparison cannot publish. The controller does not reconstruct legacy coverage from matching totals. A resumed model turn must establish and review the pinned comparison again; a finish replay retains the refusal. Before a new publication, fresh PR facts must still identify the reviewed head and base branch. If the base tip moved, GitHub compare must confirm the same merge base. An unavailable or changed comparison refuses publication; an unchanged comparison remains valid.
