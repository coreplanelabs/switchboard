# Public hygiene: the tree carries no imprint, held by a ratchet

A repository that grew inside one company is full of that company: its name in URLs and workflow files, its people in comments, its private issue numbers as provenance, its planning vocabulary (`KTD16`, `U3`) in docstrings, its Slack and account ids in fixtures, and dated retellings of incidents where a timeless rule should stand. None of it helps a reader who is not that company, and some of it is a leak. The policy is that every comment, docstring, fixture and prose line in the public tree is answerable from the repo alone; the mechanism is a check, because a policy held by discipline lasts one busy week.

The check is a ratchet, the shape the clock allowlist already uses ([tracing.md](tracing.md) item 8): every hit in the tree is counted per file and class in a committed list that can only shrink. The tree grows imprint nowhere from the day the check lands, and a scrub of any directory is measurable — its files leave the list. When the list is empty the check is the ordinary "none" gate and stays.

- **Code**: [`scripts/public-hygiene.mjs`](../../../scripts/public-hygiene.mjs) (the classes, the scope, the scan, the ratchet; plain JS with a `.d.mts` twin — nothing under `src/` imports it), [`scripts/public-hygiene.allowlist.json`](../../../scripts/public-hygiene.allowlist.json) (the recorded imprint, path → class → count), [`scripts/public-hygiene.allow`](../../../scripts/public-hygiene.allow) (lines allowed by name, each with its reason), [`scripts/vocabulary-check.mjs`](../../../scripts/vocabulary-check.mjs) (the sibling vocabulary ratchet: the fourteen words, the extraction, the surfaces), [`scripts/vocabulary-check.baseline.json`](../../../scripts/vocabulary-check.baseline.json) (its baseline, path → word → count).
- **Tests**: [`src/publicHygiene.test.ts`](../../../src/publicHygiene.test.ts), [`src/vocabularyCheck.test.ts`](../../../src/vocabularyCheck.test.ts).
- **Docs**: [AGENTS.md](../../../AGENTS.md) ("Comments are for the stranger"), decision records [0022](../../decisions/0022-public-tree-carries-no-imprint.md) and [0066](../../decisions/0066-a-user-meets-twelve-nouns-and-no-others-the-vocabulary-is-a-reference-page-bound-to-the-code-and-the-consistency-check-fails-a-user-surface-that-prints-an-internal-word.md) ("Two checks make it a guarantee"), the [vocabulary](../vocabulary.md).

## Behavior

1. **Five classes, one regex each, tested per line.** `names` (the company, its sibling products, people, the private Slack channel — case-insensitive; a 1Password `op://` reference is an integration's own syntax, not imprint, and a vault path that names the company is caught by the company), `trackers` (`#NNN` issue references and the private org's GitHub URLs; a line anchor, an HTML entity, a heading or a hex colour is not a tracker), `planIds` (`KTD…`, `KD…`, `OQ…`, and the bare `U1`–`U9` / `R1`–`R99` markers; a Slack user id and Cloudflare's `R2` are not), `ids` (Slack channel/user/DM ids and 32-hex account ids), `dates` (a full ISO date). A line can hit several classes; each is counted.
2. **The scope is the public tree.** Tracked files under `src/`, `deploy/`, `web/`, `scripts/`, `config/`, `docs/`, `.github/`, the root markdown and `package.json`. Not in scope: `docs/plans/` (working records, not published), `CHANGELOG.md` and generated notices (provenance lives there), lockfiles, binaries, and the ratchet's own three files and test. Decision records, and the index generated from them, carry dates and may cite PRs for provenance, so `trackers` and `dates` are not counted there.
3. **The list only shrinks.** `npm run hygiene:check` (in `check:consistency`) scans the tree and compares it with the recorded list: a file whose count in any class grew, or a file with hits that is not listed, is new imprint and fails with the line's remedy; a file whose count fell, or that vanished, fails asking for `npm run hygiene:gen` so the progress is recorded. Equal passes. `hygiene:gen` (in `fix`) writes the list from the tree — but never records growth: a class that grew, or a file with hits that is not listed, makes `gen` refuse (exit 1, the same message, nothing written) unless `-- --force` says the growth is deliberate; a stale allow entry likewise stops the write. So `npm run fix` is safe to run blindly and cannot absorb new imprint into the list. CI checks a PR merged into its base, so a branch whose base has moved fails until it rebases and re-records; growth that arrived from the base is the one legitimate use of `--force`.
4. **A legitimate line is allowed by name.** `scripts/public-hygiene.allow` holds `path<TAB>trimmed line` entries with a comment saying why (the English word "nominal", a colour that looks like an issue number, an integration's own identifier). An allowed line is skipped whole. An entry is stale — and fails the check — when its line no longer exists or no longer matches any class, so the file carries neither ghosts nor dead weight.
5. **A scrub sees what is left.** `npm run hygiene:check -- --list <prefix…>` prints every remaining hit under the given paths as `path:line`, class, text, and a count. `npm run vocabulary:check -- --list <prefix…>` does the same for the sibling's hits.
6. **The vocabulary ratchet is a sibling, over what is printed.** `npm run vocabulary:check` (in `check:consistency`) fails one of the fourteen internal words of decision record 0066 ("The internal words") where a user reads it — `session`, `lease`, `segment`, `instance`, `attempt`, `hosted` (only immediately before run/parent/pipeline; a GitHub-hosted runner is the vendor's noun), `host key`, `coordinator`, `runner` (only as "plan runner"), `admission`, `intake`, `handoff`, `wind-down`, `tier`. It reads what is printed, never what the code says to itself: string and template literals extracted (TypeScript AST — never an identifier, a comment or an import specifier) from `src/core/dispatch/` and `src/core/ship/`, the `describe:` summaries the command registry's CLI help and MCP tool list print, the text nodes of the `web/src/` templates (an attribute binding is not printed text), and the lines of the non-spec docs trees (reference, how-to, tutorials, explanation — the specs keep their internal precision). `docs/reference/vocabulary.md` and this spec quote the words by design and are exempt by path — there is no per-line allow file: a violation is rewritten in the user's nouns or it sits on the baseline.
7. **The sibling's baseline only shrinks, by the shared ratchet.** `scripts/vocabulary-check.baseline.json` records path → word → count; growth (or a new file) fails naming the file, the word and the remedy; shrinkage asks for `npm run vocabulary:gen` (in `fix`), which refuses to record growth unless `-- --force` says it is deliberate — the first recording of the brand-new baseline was that one legitimate use, alongside growth arriving from a moved base.
