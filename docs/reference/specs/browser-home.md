## Behavior

Mine groups readable work by the current provider email, with surrounding spaces removed and case ignored. A current human browser or Slack proof supplies the email; the Slack directory supplies its matching human account. Operator-configured HTTP and MCP subjects with that same email join the owner filter. A subject with conflicting or missing email entries stays unclaimed. This read projection does not change grants, authenticated source attribution, durable account links or private conversation ownership. Missing email or failed lookup retains only independently proved owners.

Optional email enrichment returns within 1.5 seconds. A stalled source retains the independently proved owner set and reports `timed_out`; a late result cannot mutate that scope. All people skips optional enrichment and reports `not_needed`. Discovery-only Slack checks share pending reads and reuse completed results for 30 seconds, with at most 1000 issuer/tenant/subject entries. Strict private-source checks do not use this cache.

All people is available to a current human operator with all actions, all channels and read access to the current organization. A finite repository scope does not hide this option. Each row still needs the operator's existing read permission. Viewing as a different person remains restricted to sessions with every grant.

Work-view resolution emits one closed diagnostic with the selected mode, Slack email lookup outcome, owner count and broad-scope flags. It carries no emails, account identifiers, repository names or exception data. A provider miss and an unavailable lookup share one outcome when the provider cannot distinguish them. A failed diagnostic sink does not change the selected scope or the returned history.

A completed person-merge review records its exact PR, reviewed head and recipient as attention, without opening a human question or restarting its driver. An owned Merge card uses the current viewer’s existing command grant and GitHub binding. It offers a saved-ID confirmation, pins the recorded head, and leaves unauthorized viewers the PR link.

1. **Durable discovery.** Home reads paginated coordinator records and their unit rows, rather than discovering work through recent runs. Held work, missing verdicts, spent budgets and stopped runs remain unresolved until durable completion or the confirmed pipeline stop settles them. Merged and already-landed units appear in separate history. Seeded dependencies and existing unit owners remain intact.
2. **Current authorization.** Every instance is admitted with the same requester, channel, repository and unknown-visibility predicate as the existing unit listing. Denied instances contribute no identifiers, text or counts. Private workers retain redacted facts unless a fresh exact original-source recipient proof permits their title, thread and recorded question. Private rounds and endings still omit report and failure text. The host rechecks every disclosed private unit and its access epoch before emission; read-only views receive no answer controls.
3. **Honest completeness.** A failed inventory page, unit read, condition read, repeated cursor or read bound yields partial data, or unavailable when nothing could be read. A failed, malformed, foreign or ambiguous condition read retains even an apparently completed unit as unresolved with unknown next action; incomplete conditions never prove absence of an obligation. Empty authorized data and a fully filtered read are distinct. Supported local proof includes more than one thousand unresolved units. A complete inventory census is not a simultaneous transaction over every unit's changing state.
4. **Personal attention.** Only an open durable condition explicitly assigned to the current actor or its current proved source identities enters personal attention. Mine can include that readable assigned question without admitting the requester's other work. A recorded accepted answer, including its consumed event, removes that same question from attention. Original requester attribution, an idle outcome and run health never invent that assignment. Automation, another person, external dependencies and unknown conditions remain visible without personal urgency. Condition reads do not change unit ownership or authorize an answer.
5. **Live work and next action.** A supplied current-authorized live-unit read identifies moving work. Absent recorded conditions, the next action is unknown. The projection never invents a retry, recovery or continuation instruction from a display status.
6. **Separate history.** Completed history is independently paginated and re-authorized on every read. Browser history uses Sunday–Saturday boundaries in the selected time zone, sorts saved completion times across the complete bounded inventory, and binds continuation to organization, reader, global owner scope, week and zone. Its next arrow never opens future history. Incomplete inventory stays explicit. The legacy service path remains ordered by stable unit key. The ordered inventory preserves its original insertion watermark; a continuation resumes the inventory page, instance and last scanned unit, so unresolved prefixes and read bounds cannot make later completed work unreachable. The cursor encrypts those internal positions with a persistent installation-owned 32-byte AES-GCM key and authenticates the organization and reader. It contains no transcript or grants and cannot be used by another reader or organization. The service never generates a startup key. If continuation is needed without a configured key or a fixed-census resume position, the result is partial with no continuation. A pending, uncertain condition or active unit effect keeps even a merged record unresolved until that obligation settles.

7. **Canonical pipeline reads.** A known pipeline is read independently of the unresolved Home scan and includes its completed units. Current access and private redaction apply to every result. Failed lookup, condition reads and per-entity bounds remain unavailable or partial rather than proving absence.

Operator notices preserve the read result. Inventory RPC failures use a fixed phase and a closed error kind; exception text, names, causes, stacks and record identifiers are omitted. Home census, pipeline and history reads summarize only their first failed read, including unavailable conditions or invalid cursors. Normal pagination bounds do not emit failure notices. The existing readiness callback identifies its awaited phase (`initialize`, `native_sources`, `reconcile` or `identity_notices`) without logging private source data.

## Manual emoji refresh

`emoji sync` uses the running host's Slack bot credential to import the full workspace catalog, including aliases. It requires the organization configuration-write grant and is available through the CLI, HTTP and MCP. It does not start a model run or a schedule. Reload dashboard pages after a successful sync.

`npm run emoji:sync -- --directory <private-cache-directory>` exports the same catalog and image format from a terminal. The token comes from `SLACK_EMOJI_TOKEN`, `SLACK_BOT_TOKEN`, `--token-file`, or a named 1Password item and field. No token value is accepted as a command argument or printed. A private export is not a production installation.

Names and image files have separate counts. The result reports the full source-name denominator, available names, distinct downloaded files and failed names. A source failure leaves the source total unknown. A repeated manual sync reuses verified images with an unchanged Slack URL. A failed replacement retains its verified cached image and reports a partial result. Native emoji aliases, legacy Slack asset URLs, names with apostrophes and JPEG uploads are supported. Catalog responses contain local paths or known Unicode, never upstream image URLs.
