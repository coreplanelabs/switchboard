# Run tracing - Plan

Line references are to the survey head `721e3c3`; file paths are given in full on first use. Main has since moved (58 commits to `5aeeb5e`, including the run ledger, see "Relation to the durable-runs plan"), so every PR re-anchors its citations at its own base before it opens; the design statements do not depend on the numbers.

## Goal Capsule

- **Objective**: one measurement primitive (a span) records every unit of work Switchboard does, from the moment a message reaches our process to the moment its first reply lands, plus every named background step and every step on the Workers, and the per-run timeline falls out of it. Every instant of a run's window belongs to exactly one of seven terms (getting ready, thinking, in tools, finishing up, Switchboard overhead, not recorded, not loaded), so a user can explain every number they see and no gap can hide.
- **Where it sits**: sits on top of the run ledger the [durable-runs plan](2026-09-08-001-feat-durable-runs-plan.md) adds; its finish-to-seal window is the ledger's `finishing`-to-`finish` window (see below). Replaces the sprinkled `Date.now` timing, the seven duration formatters and the two purpose-built timing events (`turn`, `mcp_tool_use`) with spans and one formatter.
- **Success criteria**: (1) the six duration surfaces (run page header, index row, `runs list`, history seed, friction `runMs`, Slack card) agree to the second for the same run; (2) the run page shows the seven-term shape live and on the record, closing to the header total; (3) the no-gaps test proves every awaited step in `dispatch()` runs inside a span on every golden path; (4) the clock ratchet reaches zero; (5) a real review run's page total, index row and card agree, receipted on the tracker issue.
- **Stop conditions**: any span, attr, log line or grafted record that carries free remote text, a secret or another thread's identifier; any record written before its run's seal; any surface that prints a raw span name; any change that moves the model or Slack credentials.
- **Execution profile**: one `gh stack` series of sixteen PRs (0, 1, 2a, 2b, 2c, 2d-i, 2d-ii, 3, 4, 5a, 5b, 6, 7, 8, 9, 10), each through the pr-lifecycle loop; PRs 3 and 4 ship in one release.
- **Tail ownership**: the live receipts on the tracker issue are human-gated; everything else ships autonomously.

## Glossary

- **Span**: one unit of work with a start, an end, a name and a parent. **Root**: a span with no parent; one per message. **Handle**: a span kept across a suspension point and ended explicitly; contrast **`span(fn)`**, which ends when `fn` settles.
- **Run stream**: the ordered `RunEvent`s of one registry run, served live over SSE and stored as the record's body. **Transport frame**: an SSE frame that is not a run event and enters no store. Four exist: `replay_note` (existing; a bare `data:` frame with `{ type, summary }` and no `id:`, parsed by the page's default handler at `web/src/pages/RunPage.vue:223`; a positional marker that says records are missing at this point of a stored or served stream, and therefore never a signal that nothing was lost), `replay_elided` (new; a named `event:` frame `{ fromSeq, toSeq }` written only by a live replay that chose not to send a range), `finished` (`{ finishedAt }`) and `end` (`{ sealedAt, replyOk }`), both named events. Named events carry no `id:` and never move a resuming client's cursor. **Sink**: an observer of span starts and ends. **Run-stream sink**: the one sink on the root that turns streamed spans into `span_start`/`span_end` events on a run stream. **Bind**: point a sink at its consumer (a run id, a card). **Backfill**: retained events delivered to a run's stream at bind.
- **Finish**: the agent stopped (`registry.finish`). **Seal**: the stream closed, when the first reply attempt completed or the run's branch was abandoned (`registry.seal`, new). **Snapshot**: the copy of the stream taken at finish that becomes the record body. **Sweep**: the registry's lazy eviction pass, run at the next registry call.
- **Graft**: copy spans the resident measured into the bot's run under the span that called it. **Fold**: the pure function that groups a run stream into page rows (`src/channels/runTimeline.ts`).
- **Head protection**: keeping the first events of a run when a long stream is trimmed. **Ratchet**: a checked-in allowlist a test forces to shrink.
- **Window**: `[receivedAt, finishedAt]`, the interval every duration surface reports. **Buckets**: the seven terms that partition the window, five words (getting ready, thinking, in tools, finishing up, Switchboard overhead) plus two loss terms (`not recorded`, `not loaded`). **Claim pass**: the partition's interval-union step. **Six surfaces**: run page header, index row, `runs list`, history seed, friction `runMs`, Slack card.
- **Counted / uncounted / background** span classes: see The partition.

## Who ends what

| Thing | Started by | Ended by |
|---|---|---|
| Root span | the channel adapter at its entry (`receivedAt`), through `startRequestRoot`; a fresh-turn dispatch starts its own through the same helper at its own start | `dispatch()`'s outermost `finally` ends the root it was given (drain, awaited tail, `root.end()`, fresh-turn handoff, `activeRuns--`); the adapter's `finally`, which wraps its whole body including the dedupe early return, is the backstop (`end()` is idempotent) |
| Registry run | `registry.create` | `registry.finish` (agent stopped) |
| Run stream | first `publish` | `registry.seal`; content events stop at finish, span events stop at seal, anything after seal is dropped |
| Record body | snapshot at finish (memoized) | the registered writer, run by the drain after the seal with the seal delta appended |
| Card | `io.status` at the ack | `card.done`, always through one `frame()`, which uses `finishedAt` once the run has finished |
| Everything, on SIGTERM | | the drain seals finished-but-unsealed runs and yields one event-loop turn so `end` frames are handed to the socket (best effort); the root, buffers and card die with the process; the provisional record (`writeAbandonedRunRecords`, `src/index.ts:610-618`) stamps `finishedAt` and has no `sealedAt` |

## Registry states

| State | `publish` content | `publish` span | `subscribe` | `notifyIndex` | `snapshot` | `seal(id, { replyOk })` | evicted at |
|---|---|---|---|---|---|---|---|
| live | accepted | accepted | replays, attaches | on content/lifecycle | live copy | no-op (not finished) | never |
| finished, unsealed | dropped | accepted | replays, emits `finished { finishedAt }` immediately, attaches | finish upserts and sends `finished` to attached subscribers without clearing them (the block at `runRegistry.ts:456-458` is rewritten, not deleted) | the memoized record body | stamps `sealedAt`, copies and clears the subscriber set, fires each copied `onSealed(frame)` in its own try/catch, upserts once, returns `{ events since finish, eventCount, sealedAt, replyOk }` | at the next registry call after `finishedAt + 15 min` (sweep seals first through the same internal `sealRun(run, { replyOk: undefined, upsert: false })` that `sealFromFinish` and the public `seal` wrap, then `removed`) |
| sealed | dropped | dropped | replays, emits `finished` then `end` immediately | on `markPersisted` only | same body | returns the same result (re-readable) | `sealedAt + 60 s` |
| evicted | dropped | dropped | null | none | null | `{ events: [], eventCount: undefined, sealedAt: undefined, replyOk: undefined }` | |

`seal` marks `sealedAt` and clears subscribers before firing any callback, so a re-entrant sweep is a no-op. The public `seal` is never called from `finish`; the inert 2d-i step uses a registry-internal `sealFromFinish(run)` that copies `sealedAt = run.finishedAt` (one clock read, never two) and performs no upsert, so "one index event per finish" is a property of the code path, not of two timestamps happening to agree; a ticking-clock test pins it.

## Context

Justin asked what a per-run timeline could show. The survey found the run stream stamps `at` on every event and times model turns and MCP calls, but everything before `registry.create()` and after `registry.finish()` is unstamped. A timeline built on today's data would read a 90 s wait as 40 s.

Justin's direction: build ONE generic measurement primitive, measure every unit of work down to the atom, collapse the sprinkled timing code into it, and make the timeline a side effect that structurally cannot hide gaps.

Inventory (re-counted before the record is committed): about 112 `Date.now` and 20 zero-arg `new Date()` reads in tracked non-test `.ts`/`.mjs`/`.vue` files, 9 of which compute a duration; model-turn time measured twice on purpose; seven near-duplicate duration formatters plus three inline ones including the Slack card title (`src/core/dispatcher.ts:586-589`); the resident computes `attachMs`/`mutexWaitMs`/`OpRunOk.durationMs` that nobody reads and names every step (`runOk(argv, step)`) without timing it; no tracing abstraction; the shim forwards every public request to the container with headers untouched (`deploy/cloudflare/worker.ts:206`).

## Honest scope statement

The primitive measures, as spans, every awaited step between our process receiving a message and the first reply attempt completing, on every path `dispatch()` can take, plus every named background step. Time spent in our own orchestration under an uncounted span (the head-moved re-review's git and GitHub calls, a ship pipeline's round bookkeeping, a workspace release that precedes finish on the failure path) is measured, logged, and reported as `Switchboard overhead`, by design. Outside the measurement and labelled: container cold start; CPU stolen by other concurrent runs and by timers, which lands inside whatever span is open; SDK-internal retries inside one provider call; platform delivery lag before receipt and a follow-up's wait behind the run it was parked on (`queued` captions); the reply after finish (`delivered` caption, shown only for a successful first attempt) and the release after the seal (log only); a recovery reply after a failed first attempt (unmeasured); fire-and-forget work after the reply, measured as late children of the root but never part of a duration. A refusal that never reached the ack card has no user surface; its shape reaches only the log. The 15-minute unsealed hold is reachable only when a reply never settles; it then pins that run's row and subscribers, and a leaked live-view token, until the next registry call after 15 minutes. Every open dashboard is one shim log line per SSE connection. Records roughly double in size at unchanged retention. "No gaps" means every instant of the window is attributed to a bucket, with `overhead` as the residual; an unwrapped await nested inside an existing counted `span(fn)` is not a gap but inflates that span's bucket silently, and only the per-path `dep → span` snapshot in the no-gaps test catches it.

## Relation to the durable-runs plan

The run ledger ([#603](https://github.com/coreplanelabs/switchboard/pull/603), merged 2026-09-08; resume in [#610](https://github.com/coreplanelabs/switchboard/pull/610)) already splits a run's end in two: the dispatcher takes the ledger's `finishing` phase after `registry.finish` and before anything reaches the thread, and the finish record is written through the ledger's `finish` after the reply, with events appended as they happen by a batched flusher carrying the registry `seq`. This plan's **finish** is the ledger's `finishing` and its **seal** is the ledger's `finish`: the `pendingRecords` writer the drain runs is `writeHistory`, which already routes the record through the ledger; the span events published between finish and seal append to `run_events` like every other event and the ledger's finish flushes them first; anything after the seal is dropped on both sides. The span-first drop in `fitRecordToBudget` applies to the record the ledger's `finish` receives. `stepCount` is the registry's content-event counter and is unrelated to the ledger's step records. PRs 2d-i and 2d-ii therefore land on the ledger's shape, and their citations re-anchor at the merged dispatcher (`ledgerRun?.finishing()` at the two finish sites, `writeHistory` as the one record route).

## The lifecycle in ten sentences (each checkable at the cited line)

1. A message arrives; the channel adapter reads `receivedAt = clock()` at its entry (`src/channels/slack.ts:564` before `dedupeDelivery`; `src/channels/http.ts` and `src/channels/mcp.ts` after the caller's identity is established; `src/cli.ts` at entry), calls `startRequestRoot(deps, { channel, receivedAt })`, which returns `RequestTrace { root, bindRun(runId, publish), bindCard(card) }` with the root built at that instant and its sinks (the process `LogSink`, an unbound run-stream sink, an unbound card sink), and later passes that same `receivedAt` into the `IncomingMessage` it constructs (http.ts:97, mcp.ts:193, cli.ts:383, slack.ts:614) and the `RequestTrace` into `dispatch(deps, msg, io, trace)`.
2. Every awaited step inside `dispatch()` is a `span(fn)` child of the root, created at the site where the work is started (so the repo/memory overlap at :545-576 is preserved); the root is the only handle in the request path.
3. `registry.create()` (:906, :1635, :2052) mints a run with `msg.receivedAt` in its meta, and the dispatcher immediately calls `trace.bindRun`; the sink delivers every retained event past that run's cursor, then routes live; the dispatcher then publishes `input`, `context` and `run_meta`. `trace.bindCard` is called at the ack (`io.status`, :593) and paints `setupLabel` until `run.agent` starts.
4. The agent loop runs inside `run.agent` (a command's deterministic body inside `run.command`); turns, tool calls and MCP calls are children on the same stream.
5. `registry.finish()` (:1370, :1867, :2083) stamps `finishedAt` and the status, upserts the index, and sends attached subscribers the `finished` frame; the dispatcher pushes the run id onto `sealIds` as the very next statement, takes the one snapshot (:1379) that is the record body, computes the diagnosis over the window, then fires `io.runFinished` once (:1386).
6. Between finish and seal the stream accepts span events only and subscribers stay attached, so the card close and reply are measured live (the release follows the seal and is log-only); the registered writer appends the seal delta when the drain runs it.
7. When the first reply attempt completes, success or failure, or the run's branch is abandoned without a reply, `registry.seal(id, { replyOk })` stamps `sealedAt`, closes the stream and returns the delta; anything published after seal is dropped.
8. `seal` is idempotent and never throws; the outer `finally` drains `sealIds` first, the drain pass seals every finished-but-unsealed run before exit, and the sweep seals-and-evicts a run that stayed unsealed for 15 minutes. Every record of a finished run is written by the drain, after its run's seal, and carries `sealedAt` (plus `replyOk` when a reply was attempted; the provisional records of runs that never finished are the stated exceptions and carry neither: the start tombstones at :1005 and :1695, and the SIGTERM path's `interruptedRunRecord` at :2215), so the record page and the live page agree on the `delivered` caption: each finish site registers its record writer in a `pendingRecords` holder beside `sealIds` instead of writing inline, and the drain seals, then runs every registered writer once with its `SealResult`; because the drain also runs from `dispatch()`'s outer catch and outer `finally`, a thrown command (:2076-2083) and a ship pipeline that threw (:1852-1854, whose `outcome === undefined` record at :1911 runs during unwinding today) are still written exactly once, from the outer drain.
9. Fire-and-forget work after the reply runs as late children of the root; `dispatch()`'s outermost `finally` then ends the root, and only then hands off a fresh turn, which starts its own root at that instant.
10. A refused message is a root with children and no run, emitted to the log when the root ends; when it reached the ack card, the card's close computes the shape from the root's children so far.

## Stamps and the one definition

| Stamp | Meaning | Set by |
|---|---|---|
| `receivedAt` | our process saw the message (for a fresh turn: the fresh dispatch started) | the adapter's entry from `clock()`; carried into `IncomingMessage` at the four construction sites, never from a body or args; the fresh turn destructures `earliestAt` out of `merged` before the spread at :1559-1561 (it is not an `IncomingMessage` field), writes `receivedAt: clock()` after the spread and computes `queuedBehindMs = receivedAt - earliestAt` (`mergeFollowUps` returns `earliestAt`, the minimum of its inputs' `at`, which `dispatcher.ts:517` now stamps from `clock()`) |
| `startedAt` | the run was registered | `registry.create` (unchanged; sort key and cursor) |
| `finishedAt` | the agent stopped working | `registry.finish` (unchanged; precedes the reply on every path) |
| `sealedAt` | the stream closed: the first reply attempt completed, or the branch was abandoned without one | `registry.seal`; `replyOk` is tri-state: `true` a reply attempt was made and succeeded, `false` one was made and threw, `undefined` none was made (the fall-through's command run, the outer-`finally` backstop, the sweep, an evicted run) |

Captions, never part of a duration: `queued 6m 00s before we saw it` = `max(0, receivedAt - platformOriginAt)` for a Slack message (via `tsMs`, to be exported from `src/channels/slackCatchUp.ts:129` and floored), `queued 4m 10s behind the previous run` = `queuedBehindMs` for a fresh turn (`clock` style; shown when 60 s or more; also a totals item on the friction report; two attrs on `request`, `queuedBeforeMs` and `queuedBehindMs`), and `delivered in 2s` = `sealedAt - finishedAt` (shown when `sealedAt` is known and `replyOk === true`, from the record or from the `end` frame, which agree because every record is written after its seal; it means the first reply reached the channel, a failure reply included, so a failed run can read `failed · delivered in 2s`; when `replyOk === false` the caption reads `reply failed`, and when `replyOk` is `undefined` (no first attempt was measured: the fall-through's command run answered by the agent run, a card close that threw before the reply so the recovery reply carried the answer, a backstop or sweep seal, an evicted run, a legacy record, a start tombstone or SIGTERM provisional record) nothing shows, and the how-to says so; never on the Slack card, which is painted before the reply; also stated in `docs/how-to/watch-a-run-and-check-spend.md`). ## The partition (partition.ts)

`partition(spans: SpanRecord[], { window, owner, finished, losses })`: callers on a stream (analyzer, record page, live page) use `spansFromEvents(normalizeSpans(events))` (PR 3; the identity on a schema-2 stream; `schema` reaches it from the record or the seed, never inferred from the events) and `lossesFromStream(events, elided)`, which derives `losses` as a list of `{ from, to, kind: "lost" | "elided" }` from the stream's `seq` gaps and `spans_dropped` notes (`lost`) and from the ranges the live transport reported in `replay_elided` frames (`elided`; a gap inside such a range is elided, not lost); `replay_note` markers are never consulted, so the gaps beneath them on a stored record stay losses; the done card's shape is the finish-site diagnosis (which carries the run's registry losses but, being pre-fit, not a `not recorded` the record fit adds later, the same stated divergence as the live friction read), while the eight runless closes walk the root's children so far, filtered by the streamed predicate, with `losses: []` and `finished: false` (nothing has finished; every open span runs to the paint), since the card sink cannot see `spans_dropped`. `finished` is true for a record and for a live page after the `finished` frame. `owner: "command" | "agent"` comes from `RunRecord.agent === COMMAND_RUN_AGENT`, the live seed's agent, or the root's own knowledge on the runless path. Classes from `streamSpans.ts`:

- **Counted**: `thinking` = `model.turn` (any status; the `ok` filter applies only to the 💭 line and `slow_model_turn`); `tools` = `tool.*`, `mcp.*`, `run.command` and its op-route grafts `run.command.*` when `owner === "command"` (`getting ready` otherwise); `getting ready` = `slack.receive`, `dispatch.*` including attach-route grafts and `dispatch.ship_preflight`; `finishing up` = `run.observe_workspace`, `run.pr_post_step`, `run.reading_diff_join`.
- **Uncounted** (structure only): `request`, `run.agent`, `ship.round`, `run.settle_reviewed_head`, and defensively any `post.*` that lands inside the window (none does today).
- **Background** (concurrent, non-blocking; the whole subtree is ignored by the claim pass and excluded from the ranked list): `run.reading_diff` (the baseline command started at :1110) and `run.reading_diff.upgrade` (the never-awaited upgrade at :1121, whose `span_end` may land after finish, after seal, or after the root; the last two are dropped from the stream).

Algorithm, three passes. (1) Claim pass over every known span: intervals clipped to the window (grafts also clipped to their parent span); a span whose `span_end` is absent is an open span; on a live window it contributes `[startedAt, windowEnd]`, and on a finished window, where nothing can still be running (or the process that ran it is gone) so a missing end was lost, a **counted** open span contributes `[startedAt, start of the first loss interval after startedAt]` (or `windowEnd` when no loss follows), so a truncated record cannot over-credit `getting ready` (the discriminator is `finished`, which every caller knows; uncounted and background spans are structure only, so the root and a post-window `upgrade` end are unaffected and are never a loss source); depth is over the input set with an orphan at depth 1 (a determinism rule for credit, since every cross-bucket ancestor is uncounted by the `streamSpans.ts` invariant); the first node in the total order (depth descending, `startedAt` ascending, `spanId` ascending) covering an elementary interval claims it. (2) `not recorded` = the union of `lost` intervals and `not loaded` = the union of `elided` intervals, each clipped to the window, minus instants claimed by a **counted** span, where loss intervals are `[windowStart, at(first)]` when the first stored `seq` exceeds 1 (the registry trimmed the head; always `lost`, since the protected head makes every elision interior), `[min(at(prev), at(next)), max(…)]` for each interior `seq` gap (`fitRecordToBudget` drops from the middle; the degenerate head-only case at `src/core/runRecord.ts:511-526` yields no interior gap and no loss interval, which matches `withOmittedMarkers`' existing tail contract), tagged `elided` when inside a `replay_elided` range and `lost` otherwise, and every `spans_dropped` note's `[from, to]` (`lost`). An instant inside both a `lost` and an `elided` interval is `not recorded` (`lost` wins; pinned by a fixture with a `spans_dropped` note inside an elided range), so the two unions are disjoint. (3) `overhead` = window − four counted buckets − `not recorded` − `not loaded`. The identity `window = getting ready + thinking + tools + finishing up + overhead + not recorded + not loaded` holds by construction; `not loaded` is non-zero only on a live page whose replay was elided, prints as `1m 20s not loaded (the record has the full shape)`, and is never absorbed into overhead; the record of the same run prints the buckets the elided spans would have filled, which is the stated and expected difference between the two surfaces. The identity is tested and is tested on fixtures with a concurrent batch, an MCP call inside a tool, a head-moved re-review, a command run, a fall-through (`run.command` = tools on run 1, getting ready on run 2 from the same span set), a background span, an open root and an open upgrade (`overhead > 0`, `not recorded === 0`), a middle drop with a 3 s seal delta, and head and middle truncation.

Worked example (a 4m 12s review): `slack.receive` and `dispatch.*` summing to 34 s with 2 s of `repo_context`/`memory_read` overlap → getting ready 32 s; `run.reading_diff` runs concurrently for 2 min and claims nothing; eight `model.turn` summing to 2m 30s → thinking; eleven `tool.*` summing to 56.5 s with a three-read batch overlapping 1.5 s → tools 55 s; `run.pr_post_step` 8 s → finishing up; the rest → overhead 7 s. Lede: `4m 12s — 32s getting ready · 2m 30s thinking · 55s in tools · 8s finishing up · 7s Switchboard overhead`. Rounding rule on every surface: the total and the counted buckets are floored to integer seconds (never rounded half-up, which could print a negative residual), the residual is `total − sum(printed buckets)` where the printed buckets are the four counted ones plus `not recorded` and `not loaded`, the residual is always `Switchboard overhead`, and "non-zero bucket" means non-zero after flooring, so the printed items always sum to the printed total and no bucket prints `0s`.

## Decisions (D-list)

| # | Decision | Pattern | Alternative rejected |
|---|---|---|---|
| D1 | One `span(fn)` primitive wraps every awaited step; the timeline is derived from spans, never hand-timed | Execute Around Method; Composite (span tree); Observer (sinks) | per-surface timers and a separate live-status vocabulary |
| D2 | `turn` and `mcp_tool_use` retire as emitted events; a read-time Adapter (`normalizeSpans`) serves legacy records and span-dropped records alike | Adapter; Tolerant Reader | keeping two timing records on the wire |
| D3 | A run's end is two moments, finish and seal, and every record of a finished run is written by the drain after its seal through one holder of writers | Collecting Parameter (`sealIds`, `pendingRecords`); Unit of Work (the drain) | writing the record at finish and patching it after the reply |
| D4 | The root and its two request sinks are built by one constructor and handed to `dispatch()` as one object; the sinks are Null Objects until bound | Parameter Object (`RequestTrace`); Null Object | hooks on a shared tracer |
| D5 | Out-of-run measurement is JSON log lines behind a verbosity knob plus a graft of the resident's steps into the run record; no trace store yet (trigger: an incident question the log lines cannot answer, asked twice) | Correlation Identifier (W3C `traceparent`); Anti-Corruption Layer (`sanitizeGraftedSpans`) | a trace database and dashboard |
| D6 | The partition claims each instant once (deepest counted span wins), open spans run to the window end live and are cut at the next loss on a finished window, losses are `lost` or `elided`, and overhead is the residual | interval union; the `finished` discriminator | summing span durations (double counts concurrency) |
| D7 | The analyzer takes every total and finding duration from the one normalized span set; run-denominated categories use unions | one source of truth | gap-based turns beside span-based totals |
| D8 | Production code reads the clock only through `clock()`; a checked-in allowlist shrinks to zero under a lint and an AST test | Ratchet; Virtual Clock (ticking clock test) | a one-shot sweep |
| D9 | The no-gaps test enters an async context only inside `span(fn)` through a `SpanContext` seam that is the identity in production | Strategy; Null Object | importing `async_hooks` into the primitive (breaks the Workers) |
| D10 | The leak class (remote text reaching a reply, title, state or record without strip-then-redact) is closed at the write and exit seams on the resident and at the parse boundary on the bot, permanently, before any span carries an error | Anti-Corruption Layer (`residentText()`) | per-site fixes |
| D11 | Every card paint goes through one `frame()` builder; every duration through one formatter; every surface through one `runDurationMs` | Builder; Extract Function | seven formatters, eight ad hoc closes |
| D12 | The Slack card, the index, the record and the live page share one vocabulary and one caption rule (`delivered` / `reply failed` / nothing, from a tri-state `replyOk`) | one vocabulary | a live-only status vocabulary |
