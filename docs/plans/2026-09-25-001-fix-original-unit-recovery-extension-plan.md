# One fixed original-unit recovery extension after publication repair

## Scope and serialized dependency

This is the exact follow-up to the binding/head prerequisite in [PR #2359](https://github.com/coreplanelabs/switchboard/pull/2359), addressing review finding F1 under the [request's explicit split permission](https://coreplanelabs.slack.com/archives/C0BRRHKFLCB/p1790349389682559). It does not implement or activate an extension. It leaves the original unit contract unchanged and records the unimplemented portion in a separate proposed artifact for review.

The prerequisite PR is limited to guarded legacy publication/expected-head reconstruction, atomic refresh after an authorized findings rewrite, and attributable `recovery_budget_unknown` reasons. Its acceptance is the binding/head and refusal-diagnostic tests, not extension acceptance. The parser there still accepts only `agent:ship recover unit <instanceId>:<unit>`; `for 90 more minutes` remains rejected without creating replacement work. Neither [#2341](https://github.com/coreplanelabs/switchboard/issues/2341) nor [#2350](https://github.com/coreplanelabs/switchboard/issues/2350) is fully resolved by that prerequisite.

**Why separate:** publication evidence proves who may publish which head, not who may receive more time. The current instance can lack historical caps, and a terminal unit does not reliably carry cumulative spend. The extension needs durable budget provenance and a one-use receipt that survives claim cleanup, restart and replay. Adding syntax alone would expose a command without that authority. These changes require separate review of [record 0046](../decisions/0046-a-budget-is-a-lease-carved-from-its-parent-and-one-module-proves-the-leases-fit.md) and [record 0051](../decisions/0051-a-thread-has-one-owner-for-its-life-a-message-is-one-event-in-a-chosen-mode-and-a-pipeline-idles-instead-of-ending.md), not a fallback in publication reconstruction. [Record 0073](../decisions/0073-the-ship-pipeline-dissolves-into-the-orchestrator-the-unit-machine-is-the-deterministic-atom-and-judgement-composes-units.md) remains the long-term lifecycle direction; this repair must not grow a generic renewal API.

**Order:** prerequisite reviewed and merged → one writer rebased onto the containing `main` → budget-evidence proof → one atomic entitlement/admission implementation → full boundary tests and independent review → human merge/deployment → original-requester live acceptance. No parallel extension writer and no live recovery during prerequisite repair. A missing fact or reservation conflict stops the next unit with the exact blocker; it never opens a replacement product lane.

### Implementation sequence inside that one unit

1. **Prove the inputs before granting time.** Add failing Vitest tests for a typed budget-evidence result that names exact missing/invalid/contradictory facts. Read the original cap, segment/resume timestamps, lifetime round usage, historical grant/cost policy and cumulative spend from durable records with complete attributable listings. A historical cap missing from the instance may be recovered only from a durable original admission/parent receipt explicitly recording that cap; a run profile's minutes do not prove its review-round cap. Every accounted child must belong to this original across all prior segments, with known finite nonnegative spend and no duplicate charge. Missing/truncated/unknown cost evidence refuses even when no cap is configured. Preserve provenance in the admission receipt. Do not infer zero spend from missing usage, reconstruct authority from task prose, substitute today's defaults, or treat the named lane as budget proof. If the actual legacy records cannot establish these facts, stop that lane with the exact reason rather than promise a successful recovery.
2. **Keep policy cumulative.** Resolve the original and currently effective cost policies under the resolved original requester. Any configured cost cap in either policy refuses this special extension, even with known spend; no cap removal, reset or fresh spend allowance. Preserve grants and cumulative rounds; calculate remaining rounds from the proven historical cap and all durable round/segment evidence, with any tighter current limit still binding. Zero, exhausted, missing or ambiguous remaining rounds refuses. No rounding down past work, new segment budget, extra review round, grant renewal or replacement parent is permitted.
3. **Add a one-use durable entitlement.** Use a typed extension intent, not an arbitrary duration. Gate the exact seven-way mapping and resolved caller at the deterministic recovery admission boundary, including non-chat callers; an internal transport replay can only reuse an existing receipt, never mint one. Persist the original request's message identity, requester/thread, fixed amount, admission time, absolute deadline, budget-evidence provenance and exact recovery Workflow reference together with the full-row recovery CAS. The one-shot marker belongs to the original unit and outlives `recovery`, `recoveryReceipt` and terminal cleanup. Compare the absence of a consumed entitlement under that same CAS; simultaneous requests have one winner. Do not reuse the ordinary renewable-grant counter as this entitlement.
4. **Start exactly one clock, never reset it.** The admitted extension supplies exactly 90 minutes from its durable admission time, not another original maximum lease and not 90 plus banked original time. Define the fixed allowance in `src/core/budgets.ts`; enforce the same absolute deadline at transport admission, child dispatch, post-attach publication authorization and the runtime hard stop. Slow admission, retry and restart consume that clock. A replay of the same resolved message returns the existing receipt/Workflow/deadline with no second charge or child. A different request after consumption is a second extension and refuses, even after cleanup or an unused clock. A definite create failure conditionally restores only provisional claim/binding state; it must not erase the consumed entitlement. An ambiguous CAS/create result is read back against the exact receipt before any cleanup, and an unresolved outcome retains the claim rather than refunding time or admitting again.
5. **Wire syntax only with those guards present.** Extend `parseOriginalUnitRecoveryRequest`, the dispatch dependency and composition root to carry the fixed extension intent and trusted message identity into the guarded operation. Only the exact `for 90 more minutes` suffix is supported; arbitrary durations, repeat suffixes and extra text fail before ordinary hand-off. Preserve the plain command's behavior and refusals. The original instance/unit, repo/PR/base/ref/expected full head/publication owner, requester/thread, grants, cumulative rounds and idempotency namespace never change. The physical Workflow is a new transport checkpoint only; no generated unit, replacement attempt identity, round zero, branch creation or generic renewal API.
6. **Retain all existing fences.** Reuse publication reconstruction only with same-unit durable evidence, fresh exact PR/ref/base/head facts, sole ownership and full-row CAS. Preserve authorized force-with-lease head refresh before re-review. Refuse moved/foreign/ambiguous heads, incomplete/contradictory evidence, active or rival claims, unknown ownership, CAS loss, unsupported stage and lifecycle ambiguity. Recheck the same recovery claim and deadline after asynchronous boundaries. A stale cleanup cannot release a successor or erase newer publication authority. No writable run is admitted on the strength of a parser test or an injected recovery success double.
7. **Review the lifecycle as a unit.** Add append-only decision amendments explaining the new entitlement and its evidence; update the [agent-ship spec's extension gap](../reference/specs/agent-ship.md) with exact test bindings only when those proofs pass. Run changed-set gates, rebase again, push early for CI and obtain independent review before a human merge. Do not declare any retained product PR recovered from synthetic acceptance alone.
